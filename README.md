# bball-event-detector (garbage-time-tracker)

농구 중계 영상에서 **스코어버그(점수판)를 읽어 점수 변화 이벤트를 뽑고**, **코트 라인을 기준으로 슛 위치가 2점인지 3점인지(코너·45도·탑)** 판정하는 도구입니다. GARBAGE TIME PROJECT의 자동 기록 파이프라인 1단계입니다.

지금 되는 것

| 기능 | 명령 | 결과 |
| --- | --- | --- |
| 스코어버그 점수 인식 | `scorebug-setup` → `scorebug-learn` → `scorebug-read` | `out/score_events.csv` (언제, 어느 팀이 +1/+2/+3) |
| 코트 라인 캘리브레이션 | `calibrate` | `configs/calib.json` (화면 ↔ 코트 좌표 변환) |
| 팬·줌 카메라 추적 | `track-court` | `out/court_track.npz` (프레임별 코트 변환) |
| 라인 확인 | `overlay` | 영상 위에 코트 라인을 겹친 이미지 |
| 슛 위치 기록 + 2점/3점 판정 | `click-shots` | `out/shots.csv` (시각, 팀, 등번호, 성공/실패, 2점/3점, 구역, 라인까지 거리) |
| 기록지 점검 | `check-records` | 기록지 엑셀의 이상한 값 목록 |
| 설치 점검 | `demo` | 합성 중계로 전체 흐름을 돌린 결과와 걸린 시간 |
| 기록지와 비교 | `compare` | `out/compare.xlsx` (팀·선수별 기록지 vs 자동, 3점 구역 제안) + 구역을 채운 기록지 사본 |
| 코트 점수 검증 | `score-check` | 슛 위치(코트)로 정한 자유투/2점/3점이 스코어버그 +1/+2/+3 과 맞는 비율 |
| 정확도 벤치 | `bench` | 빠른 팬·줌, 리플레이, 방송 로고, 밝은 조명, 라인 근처 슛을 넣은 합성 중계로 점수 인식·코트 추적·코트 점수 정확도 측정 |

아직 안 되는 것: 슛을 사람이 클릭하지 않아도 자동으로 찾는 기능(공·림·선수 검출 모델)은 다음 단계입니다. `click-shots`로 쌓은 기록이 그 모델의 학습·평가 데이터가 됩니다.

## 데스크톱 설치

Python 3.10 이상이 필요합니다. (Windows는 [python.org](https://www.python.org/downloads/)에서 설치할 때 "Add python.exe to PATH" 체크)

```bash
git clone https://github.com/coar0000-collab/bball-event-detector.git
cd bball-event-detector
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

pip install -e ".[dev]"
pytest            # 테스트가 모두 통과하면 설치 완료
gtt demo          # 영상 없이 합성 중계 60초로 전체 흐름 점검 (1분 이내)
```

`gtt demo`는 팬·줌하는 합성 중계 영상을 만들어 `scorebug-read` → `track-court` → `overlay` → `shot`을 실제 명령과 똑같이 돌리고, 정답과 비교한 결과와 걸린 시간(40분 경기 예상)을 보여 줍니다. 창에서 사람이 하던 단계(스코어버그 영역·숫자 등록, 코트 점 찍기)는 정답 좌표로 대신합니다. `out/demo/overlay_grid.png`에서 코트 라인이 맞게 겹쳤는지 볼 수 있습니다.

영상 파일은 `videos/` 폴더에 두면 됩니다(깃에는 올라가지 않음). 유튜브 중계를 받을 때는 [yt-dlp](https://github.com/yt-dlp/yt-dlp)를 쓸 수 있습니다. **B-LAB 등 중계사 영상을 학습·서비스에 쓰려면 채널의 허락이 필요합니다.**

```bash
pip install yt-dlp
yt-dlp -f "bv*[height<=1080][ext=mp4]+ba[ext=m4a]/b[ext=mp4]" -o videos/game1.mp4 "<유튜브 주소>"
```

## 사용 순서

아래 예시는 `videos/game1.mp4` 기준입니다. 시간(`--t`)은 초 단위입니다.

### 1. 스코어버그 점수 인식

```bash
# (1) 점수 숫자 영역 지정: 창이 뜨면 왼쪽 팀 점수 숫자만 드래그 → Enter, 오른쪽 팀도 같은 방법
gtt scorebug-setup --video videos/game1.mp4 --t 900 --home 고려대 --away 연세대

# (2) 숫자 글꼴 등록: 화면에 나온 점수를 콘솔에 입력 (예: 47 52). 0~9가 다 나올 때까지
gtt scorebug-learn --video videos/game1.mp4 --n 12

# (3) 전체 경기 읽기 → 점수 변화 이벤트 CSV
gtt scorebug-read --video videos/game1.mp4 --out out/game1_score_events.csv
```

결과 CSV의 `flag`가 `ok`면 정상(+1/+2/+3), `check`나 `correction`이면 판독 오류나 점수 정정일 수 있으니 확인합니다. 기록원이 점수를 고친 흔적은 30초 안의 앞뒤 변화와 묶어 정리합니다: 잠깐 내렸다가 되돌린 증가는 `revert`(득점 아님), 넣었다가 지운 득점은 `reverted`, +3 을 넣었다가 -1 로 고친 것은 +2 `ok`(`note`에 표시)와 `merged`가 됩니다. 몇 분 뒤에 몰아서 고친 것(예: +1, +1 을 2~3분 뒤 -2 로 지움)은 감소 전 5분 안의 같은 팀 변화를 최근 것부터 더해 감소량과 딱 맞으면 모두 `reverted`(note `늦은 정정`)로 봅니다. 딱 맞는 묶음이 없으면 `correction` 그대로 남깁니다. 점수판이 한 번 바뀐 것을 중간에 말이 안 되는 값으로 읽은 경우(실제 D201: 67→'6'→69, B-LAB: 22→'114'→24)는 30초 안에 이어진 큰 check/correction 의 합이 1~3 이면 그 합의 `ok` 하나로 합칩니다(note `오독 구간 합침`, 합이 0 이면 득점 아님). `ok`만 득점으로 셉니다.

**숫자 0~9 를 모두 실제 화면에서 등록하세요.** 등록하지 않은 숫자는 글꼴 대체 템플릿으로 읽는데, 중계 글꼴과 달라 틀리기 쉽습니다(실제 영상: '4' 가 두 조각으로 끊겨 22→24 를 114 로 읽음). 읽는 중에는 확정된 점수를 알고 있으므로, 한 번에 4점 이상 바뀌는 판독이 나오면 직전 점수 ±3 값 중 템플릿과 닮은 값으로 다시 읽습니다(끊긴 조각은 합침). 닮은 값이 없으면 읽은 값 그대로 두어, 다음 경기로 넘어가 0:0 이 되는 것 같은 진짜 큰 변화는 여러 번 읽힌 뒤 `check`/`correction`으로 나옵니다. `t_sec`는 스코어버그가 바뀐 시각이라 실제 슛보다 보통 1~5초 늦습니다. 엑셀에서 바로 열 수 있게 UTF-8(BOM)으로 저장합니다.

### 2. 코트 라인 캘리브레이션

```bash
gtt calibrate --video videos/game1.mp4 --t 900 --refine
```

- 오른쪽 `court reference` 창의 **빨간 점**이 지금 찍을 지점입니다. 영상 창에서 같은 지점을 클릭하세요.
- 안 보이는 지점은 `n`으로 건너뜁니다. 4개 이상 찍고 `f`를 누르면 노란 코트 라인이 겹쳐 보입니다.
- 노란 선이 실제 라인과 맞으면 `s`로 저장합니다. 베이스라인 점만 찍는 것처럼 한 직선 위의 점만 고르면 안 됩니다.
- 기본 규격은 FIBA(3점 6.75m, 코너 6.6m)입니다. 체육관 라인이 다르면 `gtt/court.py`의 `CourtSpec`에 규격을 추가하세요.

### 3. 카메라를 따라가며 코트 변환 계산

```bash
gtt track-court --video videos/game1.mp4 --calib configs/calib.json --step 0.2
gtt overlay --video videos/game1.mp4 --t 1500 --track out/court_track.npz --out out/check_1500.png
```

**양쪽 골대를 미리 맞춰 두세요.** 중계 카메라가 하프코트를 휙 가로지르면 반대쪽 골대 화면이 좌우만 바뀐 비슷한 모양이라, 기준이 없으면 다시 찾기가 어렵습니다. 왼쪽·오른쪽 골대가 잘 보이는 시각에서 각각 `calibrate`를 해 두고 `--calib`을 여러 번 주면, 첫 번째에서 출발하고 나머지는 놓쳤을 때 다시 찾는 기준으로 씁니다.

```bash
gtt calibrate --video videos/game1.mp4 --t 120 --refine --out configs/calib_right.json
gtt calibrate --video videos/game1.mp4 --t 15 --refine --out configs/calib_left.json
gtt track-court --video videos/game1.mp4 --calib configs/calib_right.json --calib configs/calib_left.json --step 0.2
```

빠른 패닝 때는 샘플 사이 프레임까지 이어서 카메라 이동을 계산합니다. 다음 경우에는 좌표를 내지 않습니다(틀린 좌표보다 빈칸이 낫다):

- 화면이 흐린 빠른 패닝 중 라인이 확실히 맞지 않을 때
- 라인 일치율이 0.65(`--min-score`)보다 낮을 때
- 화면에 보이는 코트 라인 줄(베이스라인·키 세 변·코너·아크 …) 가운데 실제 선과 겹치는 줄이 60% 미만이거나, 맞은 줄이 모두 평행한 가로선뿐일 때 (선 방향으로 미끄러져도 똑같이 맞아 위치가 정해지지 않음)
- 캘리브레이션 화면과 비교해 코트가 찌그러졌을 때 (키 투영 넓이가 10% 미만, 또는 화면 가운데의 코트가 훨씬 납작함). 이때는 화면 이동으로 예측한 위치를 들고 가다가 라인이 다시 맞으면 이어 갑니다.

좌표가 빈 구간이 4초(`--bridge`) 이하이고 앞뒤가 정상이면, 앞에서 화면 이동만으로 따라간 위치와 뒤에서 거꾸로 따라온 위치가 3px 안에서 서로 맞는 샘플만 채웁니다(상태 `bridged`). 앞에서 따라간 길이 뒤 정상 화면과 만나지 않으면 하나도 채우지 않습니다.

`--start`가 캘리브레이션 시각과 달라도 캘리브레이션 화면을 기준으로 시작 화면의 위치를 다시 찾습니다. 득점 장면에 코트가 비어 있으면 그 시각으로 `calibrate`를 한 번 더 하고 `--calib`에 추가해 다시 돌리면 됩니다.

**방송 그래픽 자리는 라인 정합에서 뺍니다.** 구간에서 띄엄띄엄 뽑은 화면들에서 그대로 있는 글자·테두리(스코어버그, 로고)를 찾아 상자째 빼므로, 스코어버그의 흰 숫자·테두리를 코트 라인으로 끌어 쓰지 않고, 그 뒤에 가려진 코트 라인 점은 '안 맞음'으로 세지 않습니다(`--no-graphics-mask`로 끌 수 있음). 찾은 자리는 결과 npz 에 저장돼 `click-shots`·`shot`의 라인 보정에도 쓰입니다.

카메라가 거의 안 움직이는 구간은 그래픽과 코트를 가를 수 없어 '못 찾음'이 됩니다(실제 B-LAB 앞 구간). 그래서 스코어버그 자리를 **직접 줄 수 있습니다**: `--graphics-box x,y,w,h`(원본 화면 px, 여러 번) 또는 JSON 파일 `{"boxes": [[x, y, w, h], ...], "reference_size": [1280, 720]}`(다른 해상도 영상이면 비율로 맞춤). 중계사마다 한 번 재 두면 `track-court`·`lens-fit`·`overlay`·`shot`·`click-shots`·`rejudge` 모두에 쓸 수 있습니다. `--calib`(추적 결과 없이)으로 판정할 때도 영상이 있으면 그래픽 자리를 자동으로 찾아 더합니다. 예전에는 이때 그래픽 자리가 비어, 스코어버그에 가려진 3점 라인 대신 스코어버그 윗변을 라인으로 잡아 2점으로 확정한 적이 있습니다(실제 447s).

**렌즈 휨 보정 (`lens-fit` → `--lens`).** 넓게 찍는 중계 카메라는 화면 가장자리의 곧은 라인이 휘어 보여서, 코트 변환 하나로는 가운데는 맞아도 화면 아래·옆 가장자리가 수십 px 어긋납니다(실제 영상: 스코어버그 바로 위 윙 3점 2개가 20px 어긋나 2점으로 나옴). 양쪽 골대 캘리브레이션으로 휨 정도(k1)를 재고, 휨을 편 화면에서 추적·판정합니다:

```bash
gtt lens-fit --video videos/game1.mp4 --calib configs/calib_right.json --calib configs/calib_left.json --out configs/lens.json
gtt track-court --video videos/game1.mp4 --calib configs/calib_right.json --calib configs/calib_left.json --lens configs/lens.json
```

`lens-fit`은 k1 마다 화면을 펴고 라인에 다시 맞춘 뒤, 코트 라인 점에서 실제 흰 라인 가운데까지 평균 거리(px)가 가장 작은 값을 고릅니다. 표로 보여 주며, 휨을 펴도 거의 나아지지 않으면 k1=0(보정 안 함)으로 저장합니다. `--track`을 주면 추적 결과에서 라인이 잘 맞은 화면도 더 씁니다. 캘리브레이션 JSON 은 원본 화면에서 찍은 그대로 두면 되고(편 화면으로 옮겨 다시 맞춤), 결과 npz 의 H 는 편 화면 좌표입니다. `overlay`는 편 화면에 그리고, `click-shots`는 편 화면을 보여 주되 CSV 의 `u`, `v` 는 원본 화면 좌표로 저장합니다. `shot --u --v` 도 원본 화면 좌표를 받습니다.

**라인이 안 보여도 기준 화면 여럿이 같은 자리를 가리키면 받습니다 (`consensus`).** 스코어버그 근처 윙·코너나 반코트 확대처럼 라인이 적게 보이는 화면은 라인 정합이 기준을 못 넘어 몇십 초씩 좌표가 비었습니다(실제 B-LAB: 놓침 31%, coast 28%). 다시 찾기 때 특징점으로 옮겨 온 후보들 중 **서로 다른 시각(2초 이상)의 기준 화면 둘 이상**이 화면에서 4px 안으로 같은 자리를 가리키면 그 위치를 상태 `consensus`로 냅니다. 중계 카메라는 한 자리에서 돌고 당기기만 해서 두 화면 사이가 관중석까지 통째로 화면 변환 하나이므로, 따로 맞춘 둘이 같은 답을 내면 믿을 수 있습니다. 하나뿐이거나 서로 다르면 받지 않습니다. `--no-consensus`로 끌 수 있습니다.

**놓친 뒤 다시 찾기**는 특징점이 가장 많이 맞는 후보 하나만 보지 않고, 기준 화면(캘리브레이션)마다 하나와 키프레임 중 많이 맞는 3개를 라인에 맞춰 보고 가장 잘 맞는 것을 고릅니다(실제 영상 195~206s 에서 관중에 많이 맞은 엉뚱한 키프레임 때문에 계속 놓쳤던 경우).

`overlay` 이미지에서 노란 선이 라인에 겹쳐 있으면 추적이 잘 된 것입니다. `--pred`를 주면 추적기가 그 시각에 들고 있던 예측 위치(좌표를 못 낸 coast 구간도, npz 의 `H_pred`)를 빨간 선으로 같이 그리고 상태·라인 일치율·맞은 라인 줄 수를 출력합니다. 좌표가 오래 비는 구간이 "예측은 맞는데 라인이 안 보여서"인지 "예측부터 어긋나서"인지 가를 때 씁니다. 리플레이·클로즈업 뒤에 비슷한 화면으로 돌아오면 자동으로 다시 맞추고, 못 맞추면 그 구간은 코트 좌표가 비어 있습니다(그때는 그 시각으로 `calibrate`를 다시 하고 `track-court --start`로 이어서 실행).

### 4. 슛 위치 기록과 2점/3점 판정

```bash
gtt click-shots --video videos/game1.mp4 --track out/court_track.npz --out out/game1_shots.csv
```

| 키 | 동작 |
| --- | --- |
| space | 재생/멈춤 |
| a / d, j / l | ±1초, ±5초 |
| , / . | 한 프레임 앞뒤 |
| 클릭 | 릴리스 순간 슈터 두 발 가운데 → 화면에 2점/3점, 림 쪽 발끝에서 3점 라인 바깥 가장자리까지 거리 표시 (오른쪽 위에 4배 확대 보기, 분홍 두 줄 = 3점 라인 띠) |
| Shift+클릭 | 같은 발을 다른 프레임에서 한 번 더 찍어 평균 (NEAR LINE 일 때) |
| i / o | 라인에 딱 걸친 슛을 확대 보기로 직접 판정: i = 발이 라인을 밟았거나 안쪽(2점), o = 두 발 모두 라인 뒤(3점). 다시 누르면 취소 |
| f / r | 자유투 표시 / 리플레이 화면에서 찍은 슛 표시 |
| m / x | 성공 / 실패로 저장 |
| t | 홈/원정 전환 |
| z | 마지막 기록 삭제 |
| q | 종료 |

**3점 라인은 띠로 판정합니다.** FIBA 규격의 6.75m(코너는 사이드라인에서 0.9m)는 라인 **바깥 가장자리**까지이고, 라인 폭 5cm 는 2점 구역입니다. 그래서 림 쪽 발끝이 이 띠에 조금이라도 닿으면 2점(`on_line`=True), 띠 바깥 가장자리보다 뒤에 있어야 3점입니다. 찍는 점은 두 발 가운데라서 발끝은 그보다 0.14m(`CourtSpec.foot_reach`, 신발 길이 절반) 림 쪽에 있다고 보고 계산합니다. CSV `margin_m`은 이 발끝에서 라인 바깥 가장자리까지 거리입니다(+ 3점, 0 이하 2점).

**칠해진 라인에 맞춰 보정합니다.** 코트 전체로 맞춘 변환은 군데군데 몇 px 어긋날 수 있어서, 찍은 발 주변(신발이 가리는 바로 옆은 빼고 90px 까지, 모자라면 150px 까지)에서 실제로 보이는 3점 라인을 찾아 계산한 라인과의 차이만큼 보정합니다(`line_snap_px`). 계산 라인에서 ±12px 안의 가는 흰 줄을 모두 후보로 두고 여러 조각이 같은 차이를 가리키는 값을 고르며(투표), 못 찾으면 ±28px 로 한 번 더 찾습니다. 비슷하게 많은 두 값이 나오면(나란한 다른 선) 보정하지 않습니다. 넓힌 창에서 12px 넘게 옮긴 보정 때문에 2점↔3점이 바뀌면 다른 선을 잡았을 수도 있으므로 `NEAR LINE`(사람 판정)으로 넘깁니다. 아크를 따라 라인 방향이 돌아가므로 '라인이 화면에서 통째로 밀린 양'을 맞춘 뒤 발 자리의 값을 씁니다. 수비수·슈터 몸에 가려 라인 조각이 6개보다 적게 보이면 보정하지 않고 `line hidden`으로 표시합니다. 라인이 가려져도 라인 위치는 코트 전체 변환으로 계산되므로 판정은 됩니다. 다만 발 근처 라인이 **방송 그래픽이나 화면 가장자리에 걸려** 보이지 않고 라인까지 1.2m 안이면 계산만 믿지 않고 `LINE BLOCKED`(CSV `line_hidden`=True, `near_line`=True)로 사람 판정에 넘깁니다. 발이 가려지면 발을 디딘 채인 릴리스 직전 프레임들이나 리플레이 화면에서 Shift+클릭으로 더 찍어 평균하세요.

라인에서 30cm 안쪽이거나, 그 자리에서 발 위치를 3px 잘못 찍었을 때 흔들리는 거리(`margin_sigma_m`)의 2배 안쪽이면 `NEAR LINE!`이 뜨고 CSV의 `near_line`이 `True`가 됩니다. 카메라에서 먼 코너는 1px 이 코트에서 5cm 넘게 되므로 더 넓게 잡힙니다. 이 슛들은 사람이 한 번 더 보는 것을 권합니다.

슛을 저장하기 전에 숫자키로 슈터 등번호를 치면 같이 저장되고, 이 번호로 기록지 선수와 연결됩니다. `t`(홈/원정)는 스코어버그 **왼쪽/오른쪽** 팀이라는 뜻이며, 기록지의 홈/원정과 다르더라도 `compare`가 최종 스코어로 알아서 맞춥니다.

자유투 자리(`ft_spot`)는 자유투 라인 뒤 반원(반지름 1.8m) 안입니다. 위치만으로는 자유투와 그 자리 점프슛(2점)을 가를 수 없어 자유투는 `f`로 표시합니다.

슛 하나만 빠르게 판정하려면 (`--video`를 주면 그 화면의 3점 라인으로 보정, 원본 화면 좌표):

```bash
gtt shot --track out/court_track.npz --t 1500 --u 812 --v 455 --video videos/game1.mp4
```

**슛 프레임에 코트 좌표가 없을 때 (`--video` 필요).** 스코어버그 바로 위처럼 라인이 적게 보이는 장면은 추적이 몇 초씩 좌표를 못 냅니다(실제 B-LAB 두 구간 득점 18건 중 6건). 그러면 슛 시각 앞뒤 8초(`--window`) 안의 정상 샘플에서 각각 **화면 이동만으로** 슛 프레임까지 따라옵니다. 앞에서 온 길과 뒤에서 온 길이 발 자리에서 0.2m 안으로 같은 곳을 가리킬 때만 그 위치로 판정합니다(`h_source`=`two-way`, 두 길 차이 `h_agree_m` 만큼 라인 근처 기준을 넓힘). 한쪽 길만 있으면 0.6초 안일 때만 그대로 쓰고(`near`), 더 멀면 그 화면 흰 라인에 다시 맞춰 추적과 같은 기준을 통과해야 씁니다(`verified`). 앞뒤 8초 안에 정상 샘플이 없으면(실제 B-LAB: 스코어버그 근처 장면에서 20~80초씩 정상 샘플이 없었음), 앞뒤 2분 안의 정상 화면 최대 30장(서로 2초 이상 떨어진 것)과 사람 캘리브레이션 화면을 슛 프레임과 **직접** 특징점으로 맞춥니다. 중계 카메라는 한 자리에서 돌고 당기기만 하므로 두 화면 사이는 관중석까지 통째로 화면 변환 하나입니다. 서로 다른 시각의 화면 2장 이상에서 옮겨 온 위치가 발 자리에서 0.2m 안으로 같을 때만 씁니다(`multi-view`, 같은 답을 낸 화면 수 `h_votes`). 화면 전환(리플레이·광고) 안의 슛은 이어 올 수도, 맞출 수도 없으니 좌표 없음입니다. 샘플(0.2초 간격) 사이 프레임의 슛도 가까운 샘플 H 를 그대로 쓰지 않고 화면 이동만큼 옮겨 씁니다.

**저장해 둔 발 위치를 지금 코드로 모두 다시 판정 (`rejudge`).** 코드를 고친 뒤 같은 슛들로 다시 잴 때 씁니다. 자유투 표시(`f`)와 사람 라인 판정(`i`/`o`)은 지키고, 코트만으로 낸 점수는 `court_points` 로 따로 남깁니다:

```bash
gtt rejudge --shots out/game1_shots.csv --track out/court_track.npz --video videos/game1.mp4 --graphics-box configs/graphics.json --out out/game1_shots_v2.csv
gtt score-check --score-events out/score_events.csv --shots out/game1_shots_v2.csv
```

### 5. 기록지 엑셀과 비교

기록지 엑셀(`D3 기록지_1R-11R.xlsx` 형식)은 개인 기록이 들어 있으니 `data/` 폴더처럼 깃에 올라가지 않는 곳에 두세요(`.gitignore`에 `*.xlsx` 포함).

```bash
# 기준 데이터 점검: 득점 합계 불일치, 리바운드 열 뒤바뀜, 성공 > 시도 등
gtt check-records --records "data/D3 기록지_1R-11R.xlsx"

# 하루치 중계(여러 경기)를 읽은 점수 이벤트와 슛 기록을 경기별로 비교
gtt compare --records "data/D3 기록지_1R-11R.xlsx" --game D101,D102,D103 \
    --score-events out/day1_score_events.csv --shots out/day1_shots.csv \
    --out out/compare.xlsx --apply-zones "out/D3 기록지_구역채움.xlsx"
```

- 하루 중계 하나에 여러 경기가 들어 있어도 됩니다. 점수가 0:0 근처로 돌아가는 지점에서 경기를 나누고, 기록지 최종 스코어와 가장 가까운 구간을 그 경기로 고릅니다. 스코어버그 왼쪽 팀이 기록지의 홈인지 원정인지도 스코어로 정합니다(`--left-team`으로 직접 지정 가능).
- 보고서 엑셀 시트: **팀 비교**(득점, 스코어버그 +1/+2/+3 횟수, 슛 기록의 2점/3점/구역별 시도·성공), **선수 비교**(등번호를 입력한 슛만), **3점 구역 제안**. 차이가 있는 줄은 빨간색입니다.
- **3점 구역 제안**: 기록지 [3점슛_구역체크]의 3점 시도(공식 문자중계 순서)와 영상에서 클릭한 3점 시도를 팀별로 짝지어 코너/45도/탑을 제안합니다. 결과(성공/실패), 그 순간 스코어버그 점수와 '직전 스코어', 등번호가 맞을수록 확실하게 짝짓습니다.
- `--apply-zones`를 주면 상태가 "일치"인 제안만 기록지 **사본**의 구역 칸에 채웁니다. 원본은 건드리지 않고, 이미 구역이 있는 칸은 덮어쓰지 않으며, 드롭다운·수식은 그대로 둡니다.
- 스코어버그 +2 횟수에는 자유투 2개가 한 번에 반영된 경우가 섞일 수 있어, 2점 성공 수와 정확히 같지 않을 수 있습니다. 득점 합계와 +3 횟수가 가장 믿을 만한 비교 지표입니다.
